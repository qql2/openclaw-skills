# Obsidian 归档 Skill

## 触发方式

当用户说类似以下话时触发本 skill：

- "帮我归档/整理一下 XXX 到 Obsidian"
- "把 XXX 保存到 Obsidian 笔记里"
- "记录这个到知识库"
- "归档这个内容"

### 2. 检索已有知识

在归档之前，先在 Obsidian 库中搜索相关内容，确认：
- 是否有已存在的相似笔记
- 是否有冲突或冗余的内容
- 找到合适的父节点/关联节点位置

搜索命令示例：
```bash
grep -ri "关键字" /Users/Admin1/Documents/ob/笔记/ --include="*.md" -l 2>/dev/null
```

### 3. 判断是否为 AI 来源内容

归档之前，先判断内容是否**疑似**或**已标注**为 AI 来源：

**以下情况视为 AI 来源：**
- 内容中明确标注了 `AI`、`AI生成`、`LLM`、`ChatGPT`、`Claude`、`AI答` 等关键词
- 用户归档时原文附带了类似 `#AI`、`#ai`、`#llm`、`#gpt` 等标签
- 用户口头或文字说明"这是 AI 写的"、"AI 回的"、"AI 生成的"
- 从 AI 聊天记录、AI 工具导出的内容
- 内容风格、结构、措辞明显符合 AI 生成特征（如固定的分段模式、AI 典型的总结句式）
- 你作为 AI 自己生成/整理的内容（本 skill 触发的归档本身就是 AI 操作的）

**以下情况不做标记：**
- 用户明确说不是 AI 的
- 用户自己撰写的原创内容
- 转载自人类来源（个人博客、论文、书籍等）且无 AI 改造痕迹

### 4. AI 来源的文件命名规则

如果判断为 AI 来源，文件命名时**追加 `_AI` 后缀**：

```markdown
# 正常命名（非 AI 来源）
笔记名.md

# AI 来源命名
笔记名_AI.md
```

示例：
- `React状态管理方案对比.md` → `React状态管理方案对比_AI.md`
- `关于Docker的网络模式_AI.md`（已带标记）
- `qql1笔记原则_AI.md`（AI 整理的总结）

**命名原则：**
- `_AI` 加在文件名末尾、扩展名前
- 覆盖所有文件（笔记、MOC 等），统一标注
- 如果文件名已包含 `_AI`，不重复添加
- 不影响文件内的 wikilink → 引用时用 `[[笔记名_AI]]` 即可

### 5. 定位归档位置

基于检索结果和知识库结构，确定新笔记的：
- **文件夹位置**：按知识库分类体系放置
- **父节点**：通过 `father::` 或 `base::` 或 `child::` 链接关联
- **标签**：补充合适标签便于搜索
- **关键词**：标注同义词便于检索
- 额外标注 `ai::true` 或 `#AI` 等元数据标签（可选，与 `_AI` 命名相辅相成）

### 6. 创建 / 更新笔记

遵循以下规范写入内容：

#### 链接规范
- 链接用 `[[wikilink]]` 格式（非 `mdc:` 格式）
- 链接到 AI 来源笔记时使用 `[[笔记名_AI]]`
- link 类型限制为 `child`, `father`, `base`, `build`, `use`, `beused`
- 尽量用 inline link（嵌入正文），减少块状链接
- link 不能指向不存在文件（要么新建对应文件，要么去掉链接）
- 注重层级关系，新建笔记要注明父节点并链接

#### 内容原则
- **简洁干练**：用最少篇幅表达重要内容，细节放到子级内容中
- **低冗余**：相似知识点不重复，独立出来复用
- **二八原则**：20% 篇幅概述核心（精简易懂如教小朋友），80% 篇幅深入讲解

#### 拆分原则
- 尽量拆分内容为多个文件，用嵌入格式聚合
  ```markdown
  child::![[另一笔记#段落]]
  ```
- 一个文件的标题应能概括整篇内容，否则拆分

#### 格式提示
- 用 `#` 标题层级组织结构
- 列表可以用来写步骤、清单、多层次流程分支
- 用 `**加粗**` 或 `==高亮==` 标注重要关键词
- wikilink 格式：`[[笔记名]]`

### 7. 冲突处理

如果发现已有相似内容：
- **不直接修改用户已有笔记**
- 列出冲突点，询问用户如何处理（合并、覆盖、另建）

### 8. 归档确认

完成后告知用户：
- 笔记创建/修改的位置
- 使用了哪些新链接
- 关联了哪些已有节点
- 如果是 AI 来源，特别说明文件名追加了 `_AI` 标记
